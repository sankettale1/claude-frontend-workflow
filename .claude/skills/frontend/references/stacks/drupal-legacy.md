# Stack: drupal-legacy (non-SDC theme, Sass + gulp + Bootstrap 4)

Typical setup: a Bootstrap 4 theme with templates, `dev/scss` → `css/` via gulp (+ rtlcss), and `dev/js` → `js/`. Paths below use `<T>` = theme path and `<t>` = theme machine name, from `frontend.config.json`.

## Quick rules
- Templates: <T>/templates/<group>/<Pascal>/*.html.twig (theme-hook suggestions); partials as _<name>.html.twig next to them.
- Styles: edit the Sass source (e.g. <T>/dev/scss/style/components/<Pascal>/<name>.scss) only; compiled css/ (and -rtl.css twins) come from the build.
- JS: edit the source (e.g. <T>/dev/js/components/<name>.js) only, with Drupal.behaviors + core `once` (never jQuery.once).
- Libraries: <T>/<t>.libraries.yml, one per component (plus a -rtl twin if the theme uses rtlcss), attached from the template (`is_rtl` decides which).
- Copy the header, imports and patterns of a sibling file in the same folder before writing a new one.
- After changes: <build> (in <build.cwd>), then <cacheClear>.

## Where things go

| Piece | Location | Naming |
|---|---|---|
| Template | `<T>/templates/paragraphs/<Pascal>/paragraph--<bundle>[--<view-mode>].html.twig` (also `block/`, `node/`, `views/`, `field/`) | Drupal theme-hook suggestion |
| Partial | same folder, `_<name>.html.twig` | include with `{% include '@<t>/…/_name.html.twig' with {…} only %}` or a relative path, as siblings do |
| SCSS | `<T>/dev/scss/style/components/<Pascal>/<kebab-name>.scss` | one file per component |
| Compiled CSS | `<T>/css/style/components/<Pascal>/<kebab-name>.css` + `-rtl.css` | **generated by gulp; never edit** |
| JS | `<T>/dev/js/components/<kebab-name>.js` → `<T>/js/components/` | **edit dev/ only** |
| Library | `<T>/<t>.libraries.yml`, two entries: `<lib>` and `<lib>-rtl` | `paragraph-<kebab>` or `paragraph.vm.<view-mode>` like siblings |
| Preprocess | `<T>/<t>.theme`, `<t>_preprocess_paragraph__<bundle>()` | only when Twig can't get the value cleanly |
| Spec / docs | `<T>/docs/components/<kebab-name>.md` | |

## SCSS file header (copy from a sibling; the depth of `../` must match)

```scss
@import "../../../../../node_modules/bootstrap/scss/functions";
@import "../../../../../node_modules/bootstrap/scss/mixins";
@import "../../../custom";
@import "../../../bootstrap-override/mixins";
@import "../../../mixins";

// <Component name>.
.<block> {
  --<block>-gap: #{$spacer * 2};     // component-scoped token from Sass

  &__title { … }
  &--<modifier> { … }

  @include media-breakpoint-down(md) { … }
}
```
Rules: everything is scoped under the block class (or `.paragraph--type--<bundle>`, like siblings); use `$variables` from `_custom.scss`; use the `media-breakpoint-up/down` mixins; no IDs or `!important`; write physical properties (`margin-left`), because rtlcss flips them into the `-rtl.css` file. Only add `[dir="rtl"]` rules for things rtlcss can't flip (e.g. transforms on icons). Add `@media (prefers-reduced-motion: reduce)` for any animation.

## Twig pattern

```twig
{#
/**
 * @file
 * Theme override for the <bundle> paragraph (<Component name>).
 *
 * Figma: <url>. Spec: docs/components/<name>.md
 */
#}
{%
  set classes = [
    'paragraph',
    'paragraph--type--' ~ paragraph.bundle|clean_class,
    view_mode ? 'paragraph--view-mode--' ~ view_mode|clean_class,
    not paragraph.isPublished() ? 'paragraph--unpublished',
    '<block>',
  ]
%}
{% if is_rtl %}
  {{ attach_library('<t>/<lib>-rtl') }}
{% else %}
  {{ attach_library('<t>/<lib>') }}
{% endif %}

{% block paragraph %}
  <section{{ attributes.addClass(classes) }}>
    {{ title_prefix }}{{ title_suffix }}
    <div class="container">
      {% if content.field_title|render|trim %}
        <h2 class="<block>__title">{{ content.field_title }}</h2>
      {% endif %}
      …
    </div>
  </section>
{% endblock paragraph %}
```
Render `content.field_*` (this keeps cache metadata). Test emptiness with `|render|trim`. Static strings: `{{ 'Read more'|t }}`. Use `<section>` with an accessible name only when the component is a real landmark; otherwise use `<div>`.

## JS pattern (new code: no jQuery)

```js
/**
 * @file
 * <Component name> behaviour.
 */
(function (Drupal, once) {
  'use strict';

  Drupal.behaviors.<camelName> = {
    attach: function (context) {
      once('<kebab-name>', '.<block>', context).forEach(function (el) {
        // …
      });
    }
  };
})(Drupal, once);
```

JS isn't transpiled, and gulp's ESLint step uses `ecmaVersion: 6` with `failAfterError`, so stay within ES2015 syntax (no `async`/`await`, `?.`, `??`, object spread).

## Library entries (append next to related entries)

```yaml
<lib>:
  css:
    theme:
      css/style/components/<Pascal>/<kebab-name>.css: {}
  js:
    js/components/<kebab-name>.js: {attributes: { defer: true }}
  dependencies:
    - core/drupal
    - core/once

<lib>-rtl:
  css:
    theme:
      css/style/components/<Pascal>/<kebab-name>-rtl.css: {}
  js:
    js/components/<kebab-name>.js: {attributes: { defer: true }}
  dependencies:
    - core/drupal
    - core/once
```
Leave out `js:`/`dependencies:` when there's no JS. Paths are relative to the theme folder (never start with `themes/…`).

## Build, cache and verify

- Build: `cd <build.cwd> && PATH=<build.node>:$PATH <build.command>` (from frontend.config.json) (gulp: css + cssRtl + scripts). Compiled CSS/JS **is committed** (CI doesn't build), so the build must run before committing.
- Cache: `ddev drush cr`
- RTL check: open the page under `/ar/` (Arabic) as well.
